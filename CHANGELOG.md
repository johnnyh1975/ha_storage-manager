# Changelog

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

## 0.3.2 – 2026-11-14
- Safety check sized realistically: the room for deleting follows what is deleted (three times its size, at least 512 MB, at most half of the data) instead of half the file. Room for a new backup is taken from the newest backup with the database; only without one the file size is used. The preview shows both parts.
- Purging outdated rows needs no backup: Home Assistant deletes them every night anyway. History of deleted entities, orphaned statistics and per-entity purges still get one.

## 0.3.1 – 2026-11-14
- SQLite builds without `dbstat` (seen on Home Assistant OS): sizes are no longer raw estimates but scaled to the bytes in use in the file. The panel says so, and the reason is kept for the diagnostics.
- Repack: when no method fits, the panel shows the data in the file, what an ordinary repack and the RAM variant need, and how much space to free or how much data to remove for it to fit.
- The panel content starts at the left like the tabs instead of being centred on wide screens.

## 0.3.0 – 2026-11-14
- Safety chain before anything is deleted from the database: free-space check, full SQLite integrity check (a clean result is reused for three days), and a verified backup of Home Assistant with the database (a backup with the database from the last six hours is reused). A damaged database stops every deletion and raises a repair issue. The cleanup log names the backup and the deleted entities. Option *Back up before deleting from the database* (on by default).
- Cleanups run in a safe order: backups, files and Docker images first, then the database.
- Repack with little free space: the plan is measured from the file's free pages. Incremental repack in small steps, an ordinary repack, or one with the temporary copy in RAM; an ordinary repack can switch the file to incremental mode for the future.
- Analysis in steps with short read transactions, progress and a stop button. Attribute rows shared by several entities are split between them; loose attribute rows are counted.
- New recommendation reason: entities whose rows mostly change only attributes. The detail sheet shows which attributes keep changing.
- Health checks: database (WAL size, growth, integrity, statistics issues) and backup protection (schedule, newest backup, failed attempt, offsite copy, size, encryption, database included, free space, locations, emergency kit, restore test).
- SQLite table sizes use dbstat's aggregate rows and are cached for a day; MariaDB sizes are labelled as estimates.
- Detection of Home Assistant's native per-entity recorder option.
- 133 tests.

## 0.2.0 – 2026-11-14
- Database view rebuilt around decisions: a recommendations inbox with reasons, savings, accept or dismiss, and accept-all.
- Usage protection: automations, scripts, UI helpers that read history, the energy dashboard and dashboard history cards. Conflicting settings are flagged.
- Top causes (80 % of the size), a grouping by integration with group suggestions, and the full list.
- Detail sheet: rows per day, largest attributes, usage, and the impact of each retention level.
- Effect chart of the database size with markers for changes.
- Recorder settings in the panel (retention, commit interval, auto purge, auto repack). Keys already set in YAML are locked.
- Exclude filters for domains, patterns and event types, plus cleanup of exclusions that match nothing.
- Count of outdated rows and a purge-now action.
- 90 tests.

## 0.1.2 – 2026-11-13
- Fix: SQLite index sizes are attributed to their table via `sqlite_master` (an index such as `ix_states_metadata_id` was counted for `states_meta`).
- Type-checked with `mypy --strict`; validation uses `probatio` (Home Assistant 2026.10+).
- CI rebuilt: separate HACS/Hassfest workflows, pinned tooling, 95 % line coverage per module, translation/version/link/private-data checks, CodeQL, Dependabot, tag- or button-triggered releases gated by the test suite.
- 67 tests, 99 % coverage.

## 0.1.1 – 2026-11-13
- Repair issues pass Home Assistant's translation validation (hassfest): fixable issues show their details in the fix flow.
- The fix flows show the free space and the number of pending exclusions.
- CI installs the frontend package so the tests run on GitHub.

## 0.1.0 – 2026-11-13
First release: panel (overview, database, backups, files), byte-based database analysis, per-entity retention tiers, recorder exclusions via packages, local backup rotation, file scanner, growth forecast, sensors, buttons, repair issues, actions, diagnostics and GUI Recorder import.

Tested on Home Assistant 2026.10.4 with SQLite. Not yet field-tested: the Supervisor breakdown on Home Assistant OS, MariaDB/PostgreSQL and backup rotation with real backups. Feedback is welcome.
