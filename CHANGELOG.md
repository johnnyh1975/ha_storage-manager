## 1.2.1 – 2026-11-28
Fixes from an independent review of 1.2.0. Please update.

- Undo now lasts: it also puts back the retention tier or the recording of the entities a retention change shortened (unless they were changed since), and a limit for long-term statistics waits for the next confirmed run again. Before, the next hourly or nightly run deleted the restored rows again, this time without a backup. The undo dialog lists what is set back.
- Deleting events by type no longer breaks the recorder: the deleted event data is removed from the recorder's cache. Before, the next event with the same data failed with a database error and the recorder dropped its pending writes. Only data rows of the deleted events are checked, which also keeps each step short on large tables.
- Actions (`cleanup`, `set_retention`, `run_nightly`, `analyze_database`) and the cleanup and repack buttons are for administrators only.
- Applying retention changes always shows a confirmation with the changes, what is shortened right away and the safety chain (new WebSocket command `apply_preview`); from 25 entities on the number is typed in.
- When the targeted backup has no room and the full backup takes its place, the free space is checked for it first.
- Ids passed to the cleanup of orphaned history or statistics are checked against the real orphans.
- An integrity check that could not run (locked or unreadable file) stops deletions like a damaged database does.
- The backup rotation reads the backup list fresh and does nothing when a backup location does not answer.
- Long-term statistics by age stop when the energy preferences cannot be read, instead of treating energy statistics like all others.
- Restored placeholders of entities count as dead only one hour after the start, so integrations that discover their entities have time.
- Orphaned statistics show their size in the preview and the history instead of 0 B.
- Overview: "reclaimable" now says how much *Safe cleanup* frees right away; the rest is in the database and frees disk space only after a repack.
- Dialogs: the focus moves into a dialog and back, and Escape closes it wherever the focus is; the dangerous button no longer has the focus.
- Texts no longer say that deleted history or statistics never come back, now that Undo exists.

## 1.2.0 – 2026-11-28
- Fixed: since 1.1.0 the entity list (top causes, by integration, all) was missing in the Database tab. The folder explorer of the Files tab had the same internal name and replaced it. A new check in `scripts/check_consistency.py` stops two panel parts from sharing a method name.
- Who wrote when: drag a time range in the effect chart, or pick the last 24 hours or 7 days, to see the entities and event types that wrote in it, with rows and estimated bytes (state part only). A range older than the recorder's retention is marked as incomplete. New WebSocket command `writers`.
- Stored data in the detail sheet: the raw states of an entity with their attributes, and its hourly and 5-minute statistics, newest first, 50 at a time. New WebSocket command `raw_rows` (read-only).
- Filters in the full entity list: integration, device, usage (used, not used, only dynamic), where an entity is defined (UI, YAML, YAML without `unique_id`, gone) and when it last wrote, behind *More filters*; *select all matches*. Entity rows carry `newest`, `used` and `defined_in`.
- Treemap by integration in the groups view; a click, or *As list*, opens the full list filtered to that integration.
- Typed confirmation: applying retention changes or disabling dead entities for 25 entities or more needs the number typed in.
- Interrupted changes: a cleanup, purge or undo that a restart cut short is logged as *interrupted* with what it was doing, and a warning goes to the log.
- Nightly maintenance: new option *Nightly maintenance at 04:37* (on), new action `storage_manager.run_nightly`, and the event `storage_manager_nightly_run` with `trigger`, `entities`, `statistics_rows`, `seconds` and `errors`. A failing step no longer stops the other one.
- Undo after a Home Assistant update: columns are now matched instead of refusing any file from another schema version; only a file that lacks a column the current schema needs is refused.
- Panel: the time-range result is a card of its own; long event names no longer make the Database tab wider than a phone screen; dragging on the chart no longer blocks scrolling on touch screens; the inspector shows seconds.
- `scripts/check_translations.py` also checks that every option and every action has its texts.

## 1.1.0 – 2026-11-28
- Long-term statistics by age (Settings tab): keep the hourly statistics for 6 months up to 7 years or forever, with a separate limit for the statistics the energy dashboard reads (configured, imported and its cost sensors). The plan shows rows, size and the oldest row per group. Applying runs as cleanup target `statistics_age` with preview, safety chain and targeted backup (undo); after that the nightly run keeps the limit. A shorter limit waits for the next confirmed run; a damaged database stops the nightly run. Not offered by the `cleanup` action.

Read-only, symbolic links skipped, hard links counted once, at most 200,000 entries, unreadable folders counted. Only folders of the last scan can be browsed.
- Any card or template on a storage-mode dashboard that names an entity now counts as usage. It protects dead entities and shows in the detail sheet as "Shown on"; it does not change retention advice, which still follows only cards that draw history.
- New WebSocket commands `statistics_retention`, `statistics_age_plan`, `folder_roots`, `folder_scan`, `folder_browse`.

## 1.0.0 – 2026-11-28

The first stable release. Everything the plan from the community thread and the comparison with DB Storage Manager asked for is in: per-entity retention with usage protection, rules per kind of sensor, statistics and events nobody needs, dead entities, the template against attribute ballast, and now undo.

- Targeted backup with undo: before orphaned history, statistics (orphaned or unused), dead entities, events or retention changes applied at once are deleted, the affected rows are saved to a gzip-compressed NDJSON file under `.storage/storage_manager/undo/` and read back to verify the row counts. With the new option *Targeted backup with undo instead of a full backup* (on by default) this replaces the full Home Assistant backup for these cleanups; if it is not possible (more than 5 million rows, too little space, an error), the full backup runs as before. The global purge always uses the full backup. The preview names the targeted backup and its space.
- *Undo* in the history: brings the rows back on the recorder thread, matching entity ids, attributes, statistic metadata, event types and event data to what the database holds now and skipping rows that exist (so undoing twice adds nothing). It also enables dead entities again and switches statistics back on that the cleanup switched off. Files that are incomplete, from another format or from another recorder schema are refused. After the undo the recorder's id caches are reset.
- Undo files are kept 14 days and at most 1 GB (oldest first, checked daily and after every export) and appear under *Files* as *Backups for Undo*.
- New WebSocket commands `storage_manager/undo_preview` and `storage_manager/undo`; `overview` lists `undo_available`; `clean` returns `undo`.
- The dead-entity cleanup keeps the full list of disabled entities in the history (needed to enable them again on undo).
- The cost and compensation sensors the energy integration creates count as used by the energy dashboard, so they are never suggested for *Don't record*.
- Undoing a cleanup takes its bytes off the *freed in total* figure.

## 0.9.0 – 2026-11-22
- Dead entities (database view): entities that have been `unavailable` for at least 7 days without a real value in the database, entities their integration no longer provides (restored placeholders), and entities from YAML without a `unique_id`. Integrations that are not loaded are left out. Entities used by automations, scripts, helpers, dashboard history or statistics cards, the energy dashboard or YAML are listed with their usage and cannot be selected; YAML entities without a registry entry get a hint to remove the definition.
- Disable selected dead entities in the registry, or disable them and delete their history and long-term statistics after the safety chain (target `dead`, needs an explicit selection and is not offered by the `cleanup` action). Entities Storage Manager disabled are listed and can be enabled again; an entity someone else disabled in the meantime is left alone. Shown as a recommendation in the overview.
- Lean copy as a template (detail sheet) for entities whose attributes fill the database: YAML for a template sensor (or binary sensor for on/off domains) with the state, unit and classes of the original, optional entities for single attributes, the entity ids they will get, and the dashboards, statistics cards, history helpers and energy dashboard that read the original's history and should switch. Names follow the panel language.
- New WebSocket commands `storage_manager/dead_entities`, `disable_dead`, `enable_dead` and `attribute_template`; `preview` accepts `entity_ids`.
- README: the known limitations about usage detection were out of date since 0.8 and are corrected.

## 0.8.0 – 2026-11-15
- Statistics nobody needs (database view): long-term statistics are never deleted by Home Assistant. Storage Manager lists them for signal, uptime, IP, firmware and time sensors that no energy dashboard or statistics card shows, for disabled entities, and for imported statistics without a new row for 90 days. Switching off removes the `state_class` through `homeassistant: customize:` in the managed package (after a restart no statistics are compiled) and deletes the existing statistics; leftovers compiled until the restart are cleared on start and every night. Battery, temperature, humidity, voltage, power, energy and current keep their statistics even on diagnostic entities. Can be switched back on.
- Delete old events by type (database view): the recorder has no purge by event type, and excluding a type only stops new rows. Events of a type are deleted in chunks on the recorder thread, together with event data nobody uses any more, after the safety chain. `state_changed` is never offered; types shown in the logbook are marked.
- `system_log` with `fire_event: true` writes every log entry as an event; this and many old `system_log_event` rows now show up as a recommendation.
- Usage now covers YAML helpers (statistics, history_stats and filter sensors from YAML or packages protect their source's history), literal mentions in all YAML files of the config folder (packages, templates, scenes) with file and line, statistics cards on dashboards, and templates that loop over a whole domain.
- Purges are waited for until the rows are really gone: `recorder.purge_entities` returns as soon as the purge is queued, and large purges queue themselves again in batches. Freed space, the analysis and the history no longer run ahead of the purge.
- The analysis keeps the newest row per statistic and an estimated size per statistic and per event type.
- New WebSocket commands `storage_manager/unused_statistics` and `storage_manager/statistics_on`; `preview` and `clean` accept `statistic_ids` and `event_types`, `clean` the targets `unused_statistics` and `events`.

## 0.7.0 – 2026-11-14
- What if: the Settings tab estimates for 3, 5, 7, 14 and 30 days (and the value typed in) how much state history another global retention frees or adds. Own retention per entity is respected; events and statistics are not included. Shown even when the retention is set in your own YAML.
- Sudden heavy writers: the analysis learns each entity's usual rows per day (moving average, once a day). An entity that writes at least ten times as much and at least every 30 seconds, or a new entity that writes every 5 seconds, shows up in the database health card and as a repair issue. "Mark as normal" takes the new rate as usual. Excluded entities and entities kept for an hour only are not flagged.
- Debug logging left on: loggers set to debug (logger configuration, "Enable debug logging", `logger.set_level`) appear as a recommendation in the overview with the integrations and, once noticeable, the size of the log file.
- New WebSocket commands `storage_manager/retention_whatif` and `storage_manager/ack_writers`.

## 0.4.0 – 2026-11-14

## 0.3.2 – 2026-11-14
- Safety check sized realistically: the room for deleting follows what is deleted (three times its size, at least 512 MB, at most half of the data) instead of half the file. Room for a new backup is taken from the newest backup with the database; only without one the file size is used. The preview shows both parts.
- Purging outdated rows needs no backup: Home Assistant deletes them every night anyway. History of deleted entities, orphaned statistics and per-entity purges still get one.

## 0.3.0 – 2026-11-14
- Safety chain before anything is deleted from the database: free-space check, full SQLite integrity check (a clean result is reused for three days), and a verified backup of Home Assistant with the database (a backup with the database from the last six hours is reused). A damaged database stops every deletion and raises a repair issue. The cleanup log names the backup and the deleted entities. Option *Back up before deleting from the database* (on by default).
- Cleanups run in a safe order: backups, files and Docker images first, then the database.
- Repack with little free space: the plan is measured from the file's free pages. Incremental repack in small steps, an ordinary repack, or one with the temporary copy in RAM; an ordinary repack can switch the file to incremental mode for the future.
- Analysis in steps with short read transactions, progress and a stop button. Attribute rows shared by several entities are split between them; loose attribute rows are counted.
- New recommendation reason: entities whose rows mostly change only attributes. The detail sheet shows which attributes keep changing.
- Health checks: database (WAL size, growth, integrity, statistics issues) and backup protection (schedule, newest backup, failed attempt, offsite copy, size, encryption, database included, free space, locations, emergency kit, restore test).
- SQLite table sizes use dbstat's aggregate rows and are cached for a day; MariaDB sizes are labelled as estimates.
- Detection of Home Assistant's native per-entity recorder option.
- 133 tests.
