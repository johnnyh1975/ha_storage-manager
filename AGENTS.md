# Rules for contributors and coding assistants

> *Generated by [aurora@aurora-smart-home (ha-integration-dev skill)](https://github.com/tonylofgren/aurora-smart-home)*

Storage Manager deletes data. These rules exist so that it never deletes the wrong thing.

1. **Every fix comes with a test that fails without it.** Run `bash scripts/check_all.sh`; every module needs 95 % line coverage.
2. **Only catalogued paths.** Files are deleted only through `files.HOG_DEFINITIONS`, inside the config directory, never through symlinks. New categories need a test that proves paths outside are untouched.
3. **Preview first.** Every destructive action has a dry run (`async_preview` / `dry_run`) and a confirmation in the panel or repair flow. Backups: the only copy of a backup is never deleted while `require_offsite` is on.
4. **No private Home Assistant APIs without a fallback.** If an internal (e.g. `recorder.tasks.SynchronizeTask`) is unavoidable, guard the import and keep working without it.
5. **No private data** in code, tests, docs or screenshots: no real e-mail addresses, IPs, tokens, home paths or entity names from a real home. `scripts/check_private_data.py` enforces the obvious cases.
6. **Texts in all languages.** Change `strings.json`, every `translations/*.json` and both dictionaries in `frontend/src/i18n.js` together. `scripts/check_translations.py` checks keys and placeholders.
7. **Panel changes are rebuilt.** Edit `frontend/src`, run `npm run build` in `frontend/`, commit the bundle.
8. **Releases are the maintainer's job.** Pull requests do not bump versions or add `release-notes/` files.
9. **Typing.** `mypy --strict` must pass without ignores in the integration code.
