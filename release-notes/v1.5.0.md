# Storage Manager 1.5.0

Tested on MariaDB and PostgreSQL, a way out when the disk is nearly full, and a guard against recorder schema changes.

- **MariaDB and PostgreSQL are tested.** The whole test suite runs on both in CI. For a database on another machine, the space check before deleting no longer counts this disk for work that happens there; the MariaDB add-on counts as this disk, and the safety backup now includes it. MySQL is not tested; the panel says so.
- **Emergency path.** With less than 1 GB free, the overview leads through three steps: free space outside the database first, then delete the biggest causes nobody needs one at a time (without a backup, after you confirm, checking the free space before every step), then give the room back with a repack.
- **Schema guard.** If a Home Assistant update changes the recorder tables Storage Manager reads, its database functions switch off with a repair issue instead of failing halfway. Backups, files and retention keep working.
- **Large databases.** Load tests with ten million rows; the backup for undo is faster on large tables.
