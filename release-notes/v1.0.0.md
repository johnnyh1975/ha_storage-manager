# Storage Manager 1.0.0

The first stable release. Storage Manager now covers what the community asks for most when the recorder database grows: per-entity retention with usage protection, rules per kind of sensor, statistics and events nobody needs, dead entities, a template against attribute ballast, backup rotation and disk health. 1.0 adds the missing safety net:

**Undo for database cleanups.**

Until now, every deletion in the database waited for a full Home Assistant backup. That is safe, but slow on large installations, and getting a few deleted entities back meant restoring everything.

Now Storage Manager saves just the rows it is about to delete: the history of orphaned or dead entities, statistics, events, or the part of a history you shortened right away. The file is small (159,000 states fit into 4 MB in testing) and is checked before anything is deleted. The history in the overview then shows *Undo*:

- the rows come back exactly as they were, including attributes, statistic metadata and event data
- dead entities are enabled again, statistics that were switched off are switched back on
- what was recorded since stays, rows that already exist are skipped, so undoing twice changes nothing

This replaces the full backup for these cleanups (option *Targeted backup with undo instead of a full backup*, on by default). If the targeted backup is not possible (more than 5 million rows, too little space), the full backup runs as before. The global purge always uses the full backup.

Undo files are kept for 14 days and at most 1 GB. Undo is refused after a Home Assistant update that changed the database schema; the full backup is the way back then.

Also in 1.0.0: the cost and compensation sensors the energy integration creates now count as used by the energy dashboard, so they are never suggested for *Don't record*.
