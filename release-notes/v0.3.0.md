## Safety before deleting
Before Storage Manager deletes anything from the database (history of deleted entities, orphaned statistics, outdated rows, retention changes applied at once), it now runs three checks:

1. **Free space** for the work and for a backup.
2. **Integrity**: SQLite's full `PRAGMA integrity_check`. A clean result is reused for three days. A damaged database stops every deletion and raises a repair issue.
3. **A verified backup** of Home Assistant including the database, sent to the locations of your automatic backups (or the local one). A backup with the database from the last six hours is reused instead.

The preview shows these steps before you confirm. If the backup fails, nothing is deleted; you can then decide to continue without one. The cleanup log names the backup and the deleted entities. The option *Back up before deleting from the database* is on by default.

Cleanups now run in a safe order: backups, files and Docker images first, then the database.

## Repack with little free space
Measured on SQLite in WAL mode: an ordinary repack needs about twice the data that remains, not twice the file. Storage Manager now reads the file's free pages and picks what fits:

- **In small steps** (`incremental_vacuum`): almost no extra space. Needs the file in incremental mode.
- **Ordinary repack**, with an option to switch the file to incremental mode on the way.
- **Temporary copy in RAM** when the disk is too full but enough memory is free.

The repack runs on the recorder thread, as Home Assistant's own repack does.

## Large databases
- The analysis runs in steps with short read transactions, so SQLite can keep its write-ahead log small. It shows progress and can be stopped; the previous result stays.
- Attribute rows shared by several entities are split between them instead of being counted for each.
- SQLite table sizes come from dbstat's aggregate rows and are cached for a day. MariaDB sizes are labelled as estimates.

## Why rows are written
- New recommendation: entities whose rows mostly change only attributes, not the state.
- The detail sheet shows which attributes keep changing and how much of the attribute payload each takes.

## Health checks
- **Database**: write-ahead log size, growth compared with the weeks before, integrity, Home Assistant's statistics issues.
- **Backup protection**: schedule, newest backup with the database, failed automatic attempt, copy off this device, size compared with the last backups, encryption, database included, room for the next backup, unreachable locations, and two confirmations you set yourself (emergency kit saved, restore tested).

## Limits
- The integrity check exists for SQLite only.
- The repack options other than Home Assistant's own repack need SQLite and the recorder's internal task queue; without it, Storage Manager falls back to Home Assistant's repack.
