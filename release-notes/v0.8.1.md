# Storage Manager 0.8.1

## The effect chart shows the effect
The chart in the database view looked flat after changes. Three reasons, all fixed:

- **Scale from zero.** With 3.7 GB of data, 100 MB less was 3 % of the height. The scale now follows the values.
- **The wrong value.** Without `dbstat` (as on Home Assistant OS) the chart showed the file size. Shorter retention frees pages inside the file, so the file stays the same size until it is repacked. The chart now draws two lines: the data in use (file without free pages, measured fresh at every analysis) and the file. With `dbstat` the value used to come from table sizes cached for up to a day.
- **Missing markers and samples.** Cleanups that delete from the database or repack it are marked now, and each is followed by a new analysis, so the next sample comes right away.

The data line starts with the next analysis after the update. Older samples only know the file size.

## Statistics of entities no longer recorded
Entities excluded from the recorder (by Storage Manager, by YAML or by an include list) stop compiling statistics, but the old ones stay forever. They now appear as their own group under *Statistics nobody needs*. Whether an entity is recorded comes from the recorder's own filter. The energy dashboard and statistics cards still protect an entity.

## MariaDB and PostgreSQL
Documented honestly: Storage Manager is tested on SQLite only. The README has a new section *Databases* with what works where, and the panel shows a note on other engines.
