# Storage Manager 0.7.0

## What if for the global retention
The Settings tab estimates how much state history another global retention would free or add: for 3, 5, 7, 14 and 30 days, and for the value you type in. Retention set per entity is respected, so a sensor kept for 3 days is not counted twice. The estimate covers state history only, not events and long-term statistics, and more days are assumed to grow at today's rate. It is shown even when the retention is set in your own YAML, where you then change it.

## Sudden heavy writers
Each analysis compares an entity's rows per day with its usual rate, a moving average learned once a day. An alert appears in the database health card and as a repair issue when
- an entity writes at least ten times as many rows as usual and at least every 30 seconds, or
- a new entity writes every 5 seconds or more often (only once Storage Manager has a history for the others, so the first analysis after installing flags nothing).

This typically follows an update of a device or an integration. From the health card you open the entity, shorten its history or switch it off, or mark the new rate as normal. Entities that are not recorded or kept for one hour only are not flagged.

## Debug logging left on
Loggers set to debug, whether through the `logger:` configuration, the "Enable debug logging" button of an integration or `logger.set_level`, show up as a recommendation in the overview with the integrations concerned. Debug logging writes a lot, costs CPU and wears out SD cards. The size of the log file is shown once it is noticeable.
