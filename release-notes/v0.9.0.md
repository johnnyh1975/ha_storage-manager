# Storage Manager 0.9.0

Two new ways to get rid of data nobody looks at.

- **Dead entities** (database view): entities that have been unavailable for at least 7 days without a real value, or that their integration no longer provides. Select them and disable them in the registry, or disable them and delete their history and long-term statistics after the safety chain with backup. Entities that something still uses are shown with what uses them and can't be selected. Integrations that are not loaded right now are left out, so a device that is just offline for a restart doesn't show up. Everything Storage Manager disabled can be enabled again from the same card.
- **Lean copy as a template** (detail sheet): for entities whose attributes fill the database, such as weather forecasts or device status blobs. Storage Manager writes the YAML for a template sensor that carries only the state, with optional entities for the attributes you want to keep. It also lists the dashboards and helpers that read the original's history and should use the new entity. Then set the original to *Don't record*.

Dead entities only count `unavailable`, not `unknown`, because many entities are `unknown` on purpose. Undo with a targeted backup comes in a release of its own.
