## Database view: from a list to decisions
- **Recommendations inbox**: each suggestion comes with its reason (diagnostic noise, attribute-heavy, very frequent values with statistics kept, …) and the estimated saving. Accept or dismiss each one, or accept all at once. Accepted suggestions go into the draft and take effect with *Apply*.
- **Usage protection**:
  - helpers that read the history (statistics, history_stats, filter) are never shortened
  - the energy dashboard is never set to "don't record"
  - dashboard history cards set a minimum number of days
  - automations and scripts are noted

  Existing settings that break any of these are shown as conflicts.
- **Top causes** (the entities that make up 80 % of the size), a grouping **by integration** with group suggestions, and the full list.
- **Detail sheet**: rows per day, largest attributes, usage, and what each retention level means.
- **Effect chart** of the database size with markers for your changes.

## Recorder settings without YAML
- Retention, commit interval, nightly purge and auto repack. Keys you already set in YAML are shown as locked and never duplicated.
- Exclude filters for domains, patterns and event types, plus cleanup of exclusions that match nothing.
- Outdated rows are counted and can be purged on demand.

## Fixed
- Attribute share and savings are based on the calibrated byte estimate.

## Limits
Usage detection covers UI helpers and storage-mode dashboards, not YAML helpers, YAML dashboards or templates.
